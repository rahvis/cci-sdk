# Agent framework examples

Eight runnable agents, two per framework, each in a risk-sensitive domain.
In every one, a tool that carries risk (a refund, a claim payment, an
account hold, a triage message, a regulatory report) is guarded by a
calibrated CLI decision: each proposed call is allowed, sent to a human
reviewer, or blocked, and every decision carries the finite-sample
guarantee behind it. Everything runs offline and keyless by default, in a
few seconds, and with OpenAI, Azure OpenAI, Anthropic Claude, Gemini, or
Gemma on vLLM or SGLang by flag.

The documentation for these examples is at
[docs: Agent frameworks](https://cci-docs.gitdate.ink/agents).

> **Read this first.** All data here is synthetic, generated by seeded
> scripts from written, fictional policies and protocols (see
> [`data/README.md`](data/README.md)). Nothing in these examples is
> medical, financial, credit, insurance, legal or regulatory advice, and
> none of them is a medical device. A calibrated guarantee bounds an error
> rate over many decisions on data like the calibration set; it never makes
> a single decision safe or correct. Every action the guard escalates goes
> to a person, and a real deployment needs a qualified human in the loop,
> labelled data from its own traffic, audits and monitoring.

## Setup

The frameworks need Python 3.10 or later (the SDK itself supports 3.9).
From `sdk/python`, in a virtual environment, install the SDK with the
extra for the framework you want, plus the package for the agent model:

```bash
cd sdk/python
python -m venv .venv && . .venv/bin/activate

pip install -e ".[langchain,openai]" langchain-openai                  # LangChain examples
pip install -e ".[langgraph,openai]" langchain-openai                  # LangGraph examples
pip install -e ".[google-adk,openai]" "google-adk[extensions]"         # Google ADK examples
pip install -e ".[agent-framework,openai]" agent-framework-openai      # Microsoft Agent Framework examples
```

Mock mode needs only the framework extra (for example
`pip install -e ".[langchain]"`). The `openai` extra installs the OpenAI
SDK, which the OpenAI, Azure OpenAI, Gemini, vLLM and SGLang evidence
backends use. For other providers, add:

| Provider | Agent model package | Evidence model |
| --- | --- | --- |
| Anthropic Claude | `langchain-anthropic` (LangChain, LangGraph); included in `google-adk[extensions]` (ADK); `agent-framework-anthropic` (Agent Framework, beta connector) | `pip install -e ".[anthropic]"` |
| Gemini | `langchain-google-genai` (LangChain, LangGraph); built into ADK; `agent-framework-gemini` (Agent Framework, beta connector) | the `openai` extra |
| vLLM, SGLang | `langchain-openai`; LiteLLM from `google-adk[extensions]`; `agent-framework-openai` | the `openai` extra |
| OpenAI, Azure OpenAI | `langchain-openai`; LiteLLM from `google-adk[extensions]`; `agent-framework-openai` | the `openai` extra |

`pip install -e ".[all]"` installs every SDK extra at once.

## Run

All commands run from `sdk/python`. Every script has the same flags:

| Flag | Default | Meaning |
| --- | --- | --- |
| `--provider {mock,openai,azure,anthropic,gemini,vllm,sglang}` | `mock` | The agent model |
| `--evidence-provider <same choices>` | same as `--provider` | The model that scores proposed actions for the guard |
| `--store DIR` | `.cli_profiles` next to the script | Where calibration profiles are cached |
| `--recalibrate` | off | Rebuild the calibration profile from the data |
| `--interactive` | off | You approve or reject escalations at the prompt instead of the scripted reviewer |

Two scripts add one more: `--no-human-review` (both LangChain examples)
runs in batch-job mode, where escalated calls are refused with an error
`ToolMessage` and queued instead of interrupting; `--batch` (the AML
example) decides a nightly queue of 40 alerts at once with `gate_batch`.

### Mock mode (offline, keyless, deterministic)

```bash
python examples/agents/langchain/finance_refund_agent.py
python examples/agents/langchain/healthcare_patient_triage.py
python examples/agents/langgraph/insurance_claims_graph.py
python examples/agents/langgraph/clinical_summary_graph.py
python examples/agents/google_adk/aml_account_hold_agent.py
python examples/agents/google_adk/aml_account_hold_agent.py --batch
python examples/agents/google_adk/clinical_trial_screening_agent.py
python examples/agents/agent_framework/credit_underwriting_agent.py
python examples/agents/agent_framework/pharmacovigilance_agent.py
```

Each prints a banner with the domain disclaimer, the calibration profile
it is using, and then each scenario: the proposed tool call, the guard's
decision with its reason and guarantee, the review request and the
reviewer's answer when it escalates, whether the tool ran, and the agent's
reply. For example, from the LangGraph claims graph:

```text
C-3002: jewelry theft; the agent proposes the full loss and misses the sub-limit
    agent proposes: approve_claim_payment({"amount": 3700.0, "claim_id": "C-3002"})
    guard: ESCALATE  approve_claim_payment -> below the calibrated auto-approval threshold (confidence 0.416, calibrated threshold 0.854).
           guarantee: With 90% confidence, the rate of decisions that are auto-approved and wrong is at most 0.05 (RCPS, Hoeffding-Bentkus, n=320).
    graph paused at cli_human_review (thread claim-C-3002)
    review request for C-3002:
      action:    approve_claim_payment({"amount": 3700.0, "claim_id": "C-3002"})
      why:       below the calibrated auto-approval threshold (confidence 0.416, calibrated threshold 0.854).
      guarantee: With 90% confidence, the rate of decisions that are auto-approved and wrong is at most 0.05 (RCPS, Hoeffding-Bentkus, n=320).
    [simulated adjuster] edit amount to 1,000.00: Jewelry theft sub-limit applies: 1,500.00 less the 500.00 deductible.
    payment executed: 1,000.00 on C-3002
```

What mock mode is, exactly:

- **The agent model** is the framework's own fake or scripted model (a
  LangChain fake chat model with `bind_tools`, an ADK `BaseLlm` subclass,
  an Agent Framework `BaseChatClient` with the tool-calling layers). It
  proposes the scenario's tool calls from the conversation, so the real
  framework runs its real tool loop, middleware, interrupts and resumes.
- **The evidence model** is `MockEvidenceBackend(scorer=...)` with a small
  domain scorer that reads the case's features the way a fallible model
  would, with deterministic noise keyed on the case id. It never reads the
  label.
- **The calibration is real.** `LocalCLIClient` runs the same engine and
  statistics it runs with a real model; only the scores come from the
  mock.
- **The reviewer** is `_shared/review.py`: a scripted approve, edit or
  reject per case (`--interactive` asks you instead).
- Runs are deterministic: a second run reuses the cached profile and prints
  the same decisions. Each script takes one to six seconds.

### Real providers

Keys, models and endpoints come from environment variables with
placeholder defaults (see [`.env.example`](.env.example)). While a key is
still a placeholder, the script stops before any network call:

```text
--provider openai needs a real key: set OPENAI_API_KEY (see examples/agents/.env.example), or run with --provider mock.
```

The scripts do not read a `.env` file themselves. Export the variables, or
copy the file and load it into your shell (never commit real keys):

```bash
cp examples/agents/.env.example examples/agents/.env      # edit the placeholders
set -a; . examples/agents/.env; set +a
```

Then, for any script:

```bash
# OpenAI (gpt-4.1-mini by default: a non-reasoning model, so evidence uses log-probabilities)
export OPENAI_API_KEY=...
python examples/agents/langchain/finance_refund_agent.py --provider openai

# Azure OpenAI (the model is your deployment name)
export AZURE_OPENAI_API_KEY=... AZURE_OPENAI_ENDPOINT=https://YOUR-RESOURCE.openai.azure.com AZURE_OPENAI_DEPLOYMENT=...
python examples/agents/langchain/finance_refund_agent.py --provider azure

# Anthropic Claude (evidence by sampling: 8 requests per score in these examples)
export ANTHROPIC_API_KEY=...
python examples/agents/langchain/finance_refund_agent.py --provider anthropic

# Google Gemini (evidence by sampling)
export GOOGLE_API_KEY=...
python examples/agents/langchain/finance_refund_agent.py --provider gemini
```

Open-weight Gemma on your own server. Start the server with tool calling
switched on, or the agent answers in plain text, never calls a tool, and
the guard never runs:

```bash
# vLLM (port 8000)
vllm serve google/gemma-4-12B-it --max-logprobs 20 --generation-config vllm \
    --enable-auto-tool-choice --tool-call-parser gemma4
python examples/agents/langchain/finance_refund_agent.py --provider vllm

# SGLang (port 30000)
python -m sglang.launch_server --model-path google/gemma-4-12B-it --port 30000 \
    --tool-call-parser gemma4
python examples/agents/langchain/finance_refund_agent.py --provider sglang
```

`--max-logprobs 20` lets the evidence backend read the top 20
log-probabilities; `--generation-config vllm` stops vLLM from applying the
model's default `top_k` and `top_p`, which would truncate sampled evidence.
The model name must equal the server's served name (`VLLM_MODEL`,
`SGLANG_MODEL`, default `google/gemma-4-12B-it`); `VLLM_BASE_URL` and
`SGLANG_BASE_URL` point at the servers. Never expose a vLLM port publicly:
`--api-key` does not protect every route. Each script's docstring has its
exact commands; some also pass `--reasoning-parser gemma4` for the agent
model's thinking, and the Agent Framework examples add the vLLM recipe's
Gemma 4 tool chat template.

The agent model and the evidence model can differ. A common split is
Claude as the agent and Gemma on vLLM as the evidence model, which makes
each score one request instead of eight:

```bash
python examples/agents/langchain/finance_refund_agent.py --provider anthropic --evidence-provider vllm
```

With a real agent model, the proposed calls, and therefore the decisions,
can differ from the mock scenarios.

## How calibration caching works

The first run of a script calibrates its query on the bundled dataset and
writes the profile to `<store>/<profile>.json` (by default `.cli_profiles/`
next to the script). Later runs call `client.calibration_status(query)`
and reuse the profile when it still matches; that check is in
[`_shared/calibration.py`](_shared/calibration.py).

| Script | Profile |
| --- | --- |
| `finance_refund_agent.py` | `refund-approvals-v1` |
| `healthcare_patient_triage.py` | `portal-triage-v1` |
| `insurance_claims_graph.py` | `claim-payments-v1` |
| `clinical_summary_graph.py` | `discharge-claims-v1` |
| `aml_account_hold_agent.py` | `aml-holds-v1` |
| `clinical_trial_screening_agent.py` | `trial-screening-v1` |
| `credit_underwriting_agent.py` | `credit-tiers-v1` |
| `pharmacovigilance_agent.py` | `ae-seriousness-v1` |

A profile records the question it calibrates (instructions and options)
and a fingerprint of the evidence model and its settings. When either
changes (an edited prompt, a different provider or model, a different
server, a different sampling setting), the profile no longer describes the
scoring function, so the script recalibrates it automatically;
`--recalibrate` forces it. The fingerprints do not cover the context: if
you edit a policy or protocol text, or a context builder in `data/`,
regenerate the dataset and run with `--recalibrate`. Calibrating with a
new evidence model replaces the stored profile. To switch between evidence models without paying for
calibration again, give each one its own store:

```bash
python examples/agents/langchain/finance_refund_agent.py --provider openai --store .cli_profiles_openai
python examples/agents/langchain/finance_refund_agent.py --provider vllm --store .cli_profiles_vllm
```

Profile files are plain JSON: the query, both fingerprints, and one record
per example (the score and the label, not the example's context; `Claim`
profiles also keep each claim's text). For your
own services, commit them and review changes in pull requests. See
[docs: Local mode](https://cci-docs.gitdate.ink/agents/local-mode).

## What calibrating with a real model costs

Calibration scores every example once; after that, each guarded call costs
one scoring request at access level L1 (OpenAI `gpt-4.1-mini`, Azure
OpenAI, vLLM, SGLang), or 8 sampled replies at L0 (Claude, Gemini; the
examples use `sample_count=8` for them). Agent-model calls come on top.

| Script | Examples | Calibration at L1 | Calibration at L0 | Per guarded call |
| --- | --- | --- | --- | --- |
| `finance_refund_agent.py` | 320 | 320 requests | 2,560 | 1 (L1), 8 (L0) |
| `healthcare_patient_triage.py` | 320 | 320 | 2,560 | 1, 8 |
| `insurance_claims_graph.py` | 320 | 320 | 2,560 | 1, 8 |
| `clinical_summary_graph.py` | 240 drafts, 1,537 claims | 1,537 (one per claim) | 12,296 | 1 to split the draft, plus 1 (L1) or 8 (L0) per claim |
| `aml_account_hold_agent.py` | 360 | 360 | 2,880 | 1, 8; `--batch` adds 40 (320 at L0) |
| `clinical_trial_screening_agent.py` | 320 | 320 | 2,560 | 1, 8 |
| `credit_underwriting_agent.py` | 320 | 320 | 2,560 | 1, 8 |
| `pharmacovigilance_agent.py` | 300 | 300 | 2,400 | 1, 8 |

To keep L0 costs down, score with an L1 evidence model
(`--evidence-provider vllm` or `openai`) and keep Claude or Gemini as the
agent. Profiles are cached, so you pay for calibration once per evidence
model.

## Bring your own labelled data

The bundled datasets exist so the examples run; a guarantee about your
decisions needs labelled examples of your decisions.

1. **Sample real cases at random** from the traffic the guard will see,
   not a curated set of easy or hard ones, and record the decision a
   qualified reviewer made (or would have made) for each.
2. **Build each context with the guard's own context function.** Every
   example imports its context builder from its data module (for example
   `refund_context` in `data/generate_refund_requests.py`), and its
   `GuardRule(context=...)` uses the same function. Calibration contexts
   and live contexts must have the same keys, the same policy text and the
   same rendering; the guarantee holds only for the scoring function it was
   calibrated with.
3. **Write one JSON object per line**: `{"id": ..., "context": {...}, "label": ...}`.
   The label depends on the primitive:

   | Primitive | Label |
| --- | --- |
   | `Gate` | `true` if approving the proposed action would be correct |
   | `Set` | the correct option key |
   | `Interval` | the correct level |
   | `Belief` | `true` if the statement is true |
   | `Claim` | a list of `{"text": ..., "supported": true or false}`, one per claim |

4. **Calibrate** with `calibration.ensure_calibrated(client, [query], examples, recalibrate=True)`
   (examples loaded with `calibration.load_jsonl("/path/to/cases.jsonl")`),
   or directly with `client.calibrate(query, examples)`.
5. **Check the size.** `client.get_profile(name)` reports `minimum_n` and
   `recommended_n`; the recommended size is about 1,000 examples at
   `alpha=0.10` and 1,500 at 0.05. The bundled sets (240 to 400) are below
   it on purpose, so the examples run quickly.
6. **Audit and monitor.** Hold out part of your labelled data and run
   `client.audit(query, held_out)`; in production, feed labelled outcomes to
   `client.monitor(query)` and recalibrate when it alarms.

## Tests

Each framework's examples have a test module in `sdk/python/tests`
(`test_agents_langchain.py`, `test_agents_langgraph.py`,
`test_agents_google_adk.py`, `test_agents_agent_framework.py`). They load
the scripts by path, run the mock scenarios with a temporary `--store`,
and check the allow, escalate and block outcomes, whether each tool
actually ran, the reviewer's approve and reject paths, and that a real
provider with a placeholder key stops with a message naming its key. They
skip cleanly when the framework is not installed, so the core suite still
passes without any framework:

```bash
pip install pytest pytest-asyncio
python -m pytest tests/test_agents_langchain.py -q
```

## Disclaimers

- All data is synthetic. No real patient, customer, claimant, applicant,
  account or product is represented, and every policy, protocol and
  guideline is invented for the example.
- Nothing here is medical, financial, credit, insurance, legal or
  regulatory advice. None of the examples is a medical device, a clinical
  decision support system, a credit decisioning system or a compliance
  program, and none may be used to make real decisions about people.
- The guarantees are statements about rates over data exchangeable with
  the calibration set. They do not make any single decision safe, and they
  do not hold for data that differs from the calibration data.
- Keep a qualified person in the loop for everything the guard escalates,
  and follow your organization's clinical, model-risk, fair-lending and
  compliance governance.
